Agent 脚下的六层楼

你让 Agent 做一件事，它的每个动作都落在下面某一层：读文件，敲命令，发请求，查数据，存档。学 Agent 时听不懂的词，多半是这几层里的常识。这一页把六层各走一遍，每层都有能动手点的动画。

    这一层的词

    能讲清就勾上词一句话学 Agent 时在哪碰到
    文件存在硬盘上的一段数据，有名字。代码、笔记、图片、模型的权重，都是文件。Agent 的“读文件”“写文件”工具，操作的就是它。
    路径文件的地址，从外层文件夹一路写到文件名。工具调用的参数里到处是路径。报错 No such file or directory，就是按这个地址没找到东西。
    程序一份写好的指令，平时作为文件躺在硬盘上。你写的 agent.py 就是一个程序。
    进程正在运行的程序。同一个程序可以同时开出多个进程。Agent 每执行一条命令，就启动了一个进程。“杀掉进程”是强行让它停下。
    内存进程干活时用的临时空间。快，但断电或进程结束就清空。本地跑模型时说“至少要 16G 内存”，指的是它。
    硬盘长期存放文件的地方。断电不丢，比内存慢。Agent 的记忆想留到下一次对话，最终得写成硬盘上的文件，或者存进数据库。
    CPU 和 GPUCPU 是执行指令的芯片，一条一条地算。GPU 是另一种芯片，擅长同时做海量的简单计算。大模型主要靠 GPU 算，所以大家都在谈显卡。

    “在我电脑上明明能跑”是程序员最常说的一句话。问题通常不在程序，在程序周围的环境。

    这一层的词

    能讲清就勾上词一句话学 Agent 时在哪碰到
    操作系统管理硬件、给所有程序分配 CPU、内存和文件的总管。Windows、macOS、Linux 是最常见的三种。同一件事在不同系统上命令不同。Agent 干活前要先知道自己在哪种系统上。
    Linux免费、开源的操作系统。绝大多数服务器用它，通常没有图形界面，全靠命令行。云服务器和 Docker 容器里几乎都是 Linux。
    终端和 Shell终端是那个打字的窗口。Shell 是窗口里负责读懂命令的程序，常见的有 bash 和 zsh。“执行 shell 命令”是编程 Agent 最重要的工具。
    环境变量操作系统替程序保管的一组“名字 = 值”的便签，程序启动时可以读。API 密钥通常放在这里，比如 ANTHROPIC_API_KEY。它不该写进代码。
    包管理器用一条命令安装别人写好的软件。Python 用 pip，JavaScript 用 npm，macOS 上装工具用 brew。报错 ModuleNotFoundError，多半是少装了一个包。
    Docker把程序和它需要的整套环境装进一个“容器”，搬到哪台机器都照样运行。Agent 常被放在容器里干活。这个隔离出来的空间也叫沙箱，弄坏了不影响你的电脑。

    一次访问走过的路

    从你按下回车，到结果显示出来，中间有七步。

    代理和节点

    有时两台电脑之间的直路走不通。代理就是找一台两边都连得上的服务器，在中间转交。

    一个常见的困惑：浏览器能打开的网站，终端里的程序却连不上。原因通常是代理软件默认只接管浏览器，终端里的程序（包括你写的 agent）并不知道有代理。常见的解决办法有两个：给终端设置 HTTPS_PROXY 这个环境变量，或者在代理软件里打开接管全部流量的模式。

    这一层的词

    能讲清就勾上词一句话学 Agent 时在哪碰到
    客户端和服务器发起请求的一方是客户端，等着回应的一方是服务器。你的 agent 程序调用大模型时，它是客户端，模型厂商那边是服务器。
    IP 地址每台联网设备的编号，形如 203.0.113.8。127.0.0.1 永远指本机，它还有个名字叫 localhost。
    DNS把域名翻译成 IP 地址的电话簿。报错 Could not resolve host，是 DNS 没查到这个域名。
    端口一台机器上的门牌号。IP 找到机器，端口找到机器上的那个程序。localhost:3000 是本机 3000 号门后的程序。“端口被占用”是门后已经有别的程序了。
    HTTP 和 HTTPS客户端和服务器对话的固定格式：一个请求，换一个响应。HTTPS 是加密的版本。状态码要认得几个：200 成功，401 密钥不对，404 地址不存在，429 请求太频繁，500 服务器自己出错。
    路由器和节点数据从你到服务器，要经过许多中转设备接力。每一台都是网络上的一个节点。网络慢或者断，问题常常出在中间某一跳。
    代理替你转发请求的中转服务器。日常说的“节点”，多半指它。浏览器连得上、终端里连不上，通常是终端里的程序没有走代理。

    读懂一段 JSON
    
      
    JSON 只有几条规则，认得下面这七行就够用。
    
      
    
        
    
          {花括号包住一个对象，里面是一组“名字: 值”
            "name": "王芳",名字用双引号。值是文字时，也用双引号
            "age": 28,数字不加引号
            "tags": ["学生", "北京"],方括号包住一个列表，里面按顺序排着几个值

    这一层的词
    
      
    
        
    能讲清就勾上词一句话学 Agent 时在哪碰到
    
        
          
    前端和后端你看得见、点得着的页面是前端。服务器上处理请求、存取数据的程序是后端。Agent 本身大多是后端程序。聊天窗口只是它的前端。
    
          
    Python一门写起来接近英语的编程语言，AI 领域用得最多。大部分 agent 框架和示例代码用 Python 或 TypeScript 写。
    
          
    API程序之间互相调用的约定：往哪个地址发，带什么参数，会收到什么。调用大模型，就是向它的 API 发一个 HTTP 请求。
    
          
    JSON一种用花括号和方括号写数据的文本格式，人和程序都读得懂。工具的定义、工具调用的参数、模型 API 的收和发，全是 JSON。
    
          
    数据库专门存取大量数据的程序。比自己读写文件更快，也更不容易出错。Agent 的长期记忆、任务记录，常常存在数据库里。
    
          
    SQL向数据库提问的语言。SELECT 是查，INSERT 是加，UPDATE 是改，DELETE 是删。“查数据库”这个工具，通常是让模型写一句 SQL 再执行。

    这一层的词
    
      
    
        
    能讲清就勾上词一句话学 Agent 时在哪碰到
    
        
          
    Git给代码存档的工具。每次提交是一个存档点，随时能回到任何一个。Agent 把代码改坏了，靠 Git 退回去。GitHub 是存放 Git 仓库的网站。
    
          
    分支从某个存档岔出去的一条平行线。在上面随便试，不影响主线。让 Agent 在单独的分支上干活，你看过满意再合并。
    
          
    测试一段自动检查代码对不对的代码。Agent 改完代码跑测试，是它判断“我做对了没有”的主要依据。
    
          
    日志程序运行时写下的流水账：几点几分，做了什么，出了什么错。排查 agent 为什么出错，第一件事是看日志。
    
          
    定时任务让程序在固定时间自动运行。常用 cron 表达式写时间，0 9 * * * 是每天 9 点。“每天早上让 agent 汇总一遍邮件”，靠的就是它。
    
          
    部署把程序放到服务器上，让别人也能用。在自己电脑上能跑的 agent，部署之后才算上线。
    
          
    系统架构一个系统由哪几部分组成，彼此怎么通信的总体安排。多个 agent 怎么分工、谁调用谁，讨论的就是架构。

    一步一步走，看模型和 harness 各做了什么，每一步又落到了楼下哪一层。
    
      
    
        
        
      
      
      
      
      
        
        
        
      
      
      
      
    
      

    
      
      
      这一层的词
      
      
      
        
      能讲清就勾上词一句话学 Agent 时在哪碰到
      
        
          
      工具调用模型不能自己动手。它只输出一段 JSON，说想用哪个工具、参数是什么，由外面的程序执行。你给 agent 接的每一个能力，都是一个工具。
      
          
      Harness包在模型外面的那层程序：把工具交给模型，执行它的调用，把结果送回去，管权限和上下文。Claude Code 这类产品，本体就是一个 harness。
      
          
      工作流和 Agent步骤由人事先写死的是工作流。下一步做什么由模型自己决定的是 agent。能写成固定步骤的事，用工作流更稳。步骤说不准的事才需要 agent。
      
          
      Eval给 agent 准备的一套考题和评分办法。改了提示词或换了模型，靠它回答“变好了还是变坏了”。
      
          
      监控与回滚上线之后持续看日志和指标，出了问题就退回上一个好的版本。和 5 层是同一件事，只是对象从代码扩大到了提示词、工具和模型版本。
